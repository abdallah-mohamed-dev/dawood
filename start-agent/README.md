# ابدأ هنا — نقطة الدخول لأي Agent/موديل جديد

هذا المجلد مكتوب ليكون **قابلاً للقراءة من أي نموذج ذكاء اصطناعي** (Claude، GPT، Gemini، أو أي موديل تاني)، مش بس Claude. لو انت Agent جديد اتفتحت على المشروع دا لأول مرة (سواء بدل موديل قديم أو جلسة جديدة تمامًا)، اتبع الترتيب دا **بالحرف** قبل ما تكتب أي سطر كود.

> **ملحوظة:** الخريطة الشاملة للمشروع (كل الملفات ومين بيقول إيه) موجودة في [`../CLAUDE.md`](../CLAUDE.md) في جذر المشروع — دا الملف اللي المفروض يتقرا **قبل** الملف دا.

## ⚠️ القاعدة الأولى: ممنوع تبدأ كود قبل ما تقرأ كل حاجة هنا

لو خالفت الترتيب دا هتكرر أخطاء اتصلحت قبل كدا، أو هتنفذ تاسك بترتيب غلط، أو هتكسر قرار معماري متفق عليه بالفعل. القراءة دي مش اختيارية.

## دورة العمل الإلزامية لأي تاسك (بدون استثناء)

```text
 1. اقرأ ../specs/README.md — فيه تاسك شغال ولا محتاج تبدأ واحد جديد؟
 2. انسخ ../specs/_TEMPLATE.md لملف جديد واملا "المطلوب" و"الخطة التفصيلية"
 3. راجع الخطة (موديل تاني لو التاسك كبير) + خد موافقة المستخدم صراحة قبل أي كود

 5. php artisan test --compact   ← لازم كل الاختبارات تنجح (القديمة والجديدة)
 6. vendor/bin/pint --dirty --format agent
 7. لو التاسك فيه واجهة: npm run build (أو تأكد إن الأصول محدَّثة)
 8. حدّث ../docs/*.md المتأثرة لو قاعدة عمل اتغيرت
 9. ⚠️ حدّث ../USER-GUIDE.md لو فيه أي تغيير في المنطق (اقرأ القاعدة تحت)
10. علّم ✔ بند بند في ملف الـspec (مش التاسك كله دفعة واحدة)
11. حدّث فهرس ../specs/README.md بحالة التاسك
12. أضف إدخال جديد في AGENT_LOG.md (الصيغة موجودة في نفس الملف)
```

**ممنوع الانتقال لتاسك تاني قبل ما التاسك الحالي يخلّص الخطوات الاتناشر دي كاملة.**

## ⚠️ قاعدة `USER-GUIDE.md` — إلزامية

**أي تاسك بيغيّر منطق الأعمال لازم ينتهي بتاسك فرعي مخصص لتحديث [`../USER-GUIDE.md`](../USER-GUIDE.md).**

- **"تغيير منطق" يعني:** قاعدة حسابية اتغيرت، كيان/حالة جديدة، قاعدة تحقق (validation) اتضافت أو اتشالت، سلوك حذف/تعديل اتغير، شاشة جديدة، أو أي حاجة **المستخدم النهائي هيلاحظها**.
- **مش مطلوب لو:** refactor بحت، تغيير CSS/شكل، تحسين أداء، أو إضافة اختبارات بس — من غير أي أثر على سلوك المستخدم.
- الملف دا مكتوب **بلغة المستخدم العادي** — التحديث لازم يكون بنفس الأسلوب: مفيش أسماء كلاسات ولا مصطلحات تقنية.
- البند موجود جاهز في `../specs/_TEMPLATE.md` — **ممنوع حذفه، وممنوع تعليمه ✔ من غير ما تكون فعلاً فتحت الملف وعدلته.**

## قواعد لا تتفاوض عليها (ملخّص — التفاصيل في PROJECT.md وPITFALLS.md)

- **الأرقام المالية والكميات دايمًا أعداد صحيحة مقيّسة** (المبالغ ×100 قروش، الكميات ×1000) — **ممنوع نهائيًا استخدام `float`** في أي منطق أعمال. استخدم `MoneyCast`/`QuantityCast` الموجودين.
- **كل حركة خزنة لازم تعدي من `CashboxService`** — ممنوع إنشاء `CashboxTransaction` مباشرة من أي مكان تاني.
- **كل عملية بتلمس أكتر من جدول = `DB::transaction()`** واحدة، مع `lockForUpdate()` وإعادة جلب النسخة الطازة من قاعدة البيانات (مش الاعتماد على النسخة اللي جاية من الكولر) — راجع `PITFALLS.md` بند "TOCTOU".
- **ممنوع استخدام tinker أو verification scripts للتحقق** — الدليل الوحيد المقبول هو اختبارات Pest.
- **ممنوع تعديل ملفات خارج نطاق التاسك** إلا لو فيه ضرورة واضحة تتكتب صراحة في AGENT_LOG.md.
- **كل تاسك جديد يحتاج Factory + اختبارات Pest** (المسار الطبيعي + حالات الخطأ + رقم مرجعي محسوب يدويًا).
- **الألوان والخطوط تُعرَّف حصرًا في `resources/css/app.css`** عبر `@theme` — ممنوع أي hex مباشر في أي Blade file.
- **لو التاسك المطلوب "تعديل شكل/واجهة فقط"** — **ممنوع لمس أي منطق PHP في `app/`**، الشغل كله في `resources/views/` و`resources/css/`.
- **ممنوع التجريد المبكر** — 3 أسطر متشابهة أحسن من abstraction مش مطلوب (راجع `PITFALLS.md` بند 12).

## بيانات تشغيل سريعة

```bash
composer install && npm install
cp .env.example .env   # لو مش موجود بالفعل
php artisan key:generate
php artisan migrate:fresh --seed
npm run build           # أو npm run dev / composer run dev أثناء التطوير
php artisan serve       # أو استخدم Herd لو مفعّل على localhost:8000
```

- تسجيل الدخول (بيئة تطوير محلية فقط): `admin@dawood.test` / `password` (من `.env.example`).
- التطبيق عربي RTL بالكامل — لا تكتب أي نص واجهة بالإنجليزي إلا لو موجود بالفعل في الكود.
