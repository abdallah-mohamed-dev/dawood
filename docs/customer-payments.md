# مدفوعات العملاء

## الدفعة (CustomerPayment)

| الحقل | النوع | ملاحظات |
|---|---|---|
| `room_id` | FK | مطلوب |
| `amount` | مبلغ (قروش) | يجب أن يكون أكبر من صفر |
| `paid_at` | تاريخ | تاريخ الدفعة الفعلي |
| `note` | نص | اختياري |

## المدفوع والمتبقي — محسوبان دائمًا

```text
Room::paidAmount()     = SUM(customer_payments.amount) لكل دفعات هذه الغرفة
Room::remainingAmount() = Room.sale_price - paidAmount()
```

**قرار متعمد:** `paid_amount` **لا يُخزَّن** كحقل منفصل على الغرفة. يُحسب دائمًا من مجموع الدفعات الفعلية. هذا يمنع نهائيًا أي احتمال لعدم تطابق (drift) بين الرقم المعروض وسجل الدفعات — لو حُذفت دفعة، الرقم يتحدث تلقائيًا لأنه مُشتق لا مُخزَّن.

## منع تجاوز المتبقي

أي دفعة تجعل `paidAmount() > sale_price` **تُرفض** بـvalidation واضح يوضح المتبقي الفعلي المسموح به.

### مثال رقمي

```text
sale_price = 30,000 ج.م

دفعة 1: 10,000 → paid = 10,000، remaining = 20,000 ✅
دفعة 2: 25,000 → المجموع سيكون 35,000 > 30,000 → مرفوضة، رسالة: "المتبقي 20,000 فقط"
دفعة 2 (مُعدَّلة): 20,000 → paid = 30,000، remaining = 0 ✅
```

## الربط بالخزنة

كل دفعة تُنشئ تلقائيًا حركة خزنة `in` بنفس المبلغ، عبر `CashboxService`، من نوع (`kind`) = `customer_payment`. لا يوجد أي إدخال خزنة منفصل عن الدفعة نفسها.

## الحذف والتعديل

- **حذف** دفعة → تُحذف حركة الخزنة المرتبطة بها في نفس الـtransaction. `paidAmount()` يتحدث تلقائيًا (لأنه محسوب).
- **تعديل** مبلغ دفعة → تُحدَّث حركة الخزنة المرتبطة لنفس المبلغ الجديد (وليس حركة إضافية).

### مثال

```text
دفعة بقيمة 10,000 محذوفة → paid ينقص 10,000، والخزنة تنقص 10,000، ولا تبقى حركة يتيمة.
```

## القيم غير المسموحة

- مبلغ ≤ 0 → مرفوض.
- دفعة لغرفة `cancelled` → مرفوضة منطقيًا (الغرفة الملغاة لا يُفترض أن تستقبل مدفوعات جديدة؛ التطبيق التفصيلي في Task 5/6).
