# نطاق الـMVP

## داخل النطاق (مؤكَّد)

- مصادقة يدوية (Login/Logout) لأدمن واحد ثابت، بدون تسجيل حسابات.
- إدارة العملاء والغرف، مع حالات الغرفة الأربع (`draft` / `in_progress` / `completed` / `cancelled`).
- إدارة المخزون: تصنيفات، مواد، دفعات شراء (Batches)، تكلفة FIFO.
- صرف الخامات للغرف وحساب تكلفتها.
- مدفوعات العملاء وربطها بالخزنة.
- المصروفات الإدارية وبنودها.
- الخزنة: رصيد افتتاحي، حركات مشتقة فقط من عمليات حقيقية، رصيد وسجل حركات.
- الشركاء: نسب، نصيب من الربح، سحوبات.
- حساب صافي الربح مع الفصل الكامل بين الأساس النقدي والاستحقاقي.
- واجهة Tailwind بسيطة، عربية، RTL، بألوان وخط مركزيين (Design Tokens).

## خارج النطاق (مؤجَّل لما بعد الـMVP)

| البند | السبب |
|---|---|
| Dashboard متقدم / Charts | تعقيد غير ضروري في هذه المرحلة |
| Notifications | لا حاجة فعلية بأدمن واحد |
| PDF / Excel export | يُضاف عند الحاجة الفعلية من العميل |
| بحث متقدم / Elasticsearch | لا حجم بيانات يستدعيه بعد |
| إدارة موردين كاملة، أوامر شراء | خارج نطاق المخزون المبسط الحالي |
| Workflow تصنيع متقدم | الحالات الأربع للغرفة كافية للـMVP |
| معايير محاسبية كاملة (IFRS...) | حساب ربح مبسط كافٍ للغرض الحالي |
| فروع متعددة | ورشة واحدة فقط |
| مستخدمون متعددون / Roles & Permissions | أدمن واحد فقط |
| Audit log متقدم | خارج النطاق حاليًا |
| تطبيق موبايل / API كاملة | واجهة Blade فقط |
| مساهمات رأسمال الشركاء | فقط نصيب الربح والسحوبات مطلوبان الآن |
| تقارير بفترات زمنية (فلاتر تاريخ) | الـMVP يحسب الإجمالي التراكمي فقط |
| مرتجعات مشتريات للموردين | غير مطلوب في هذه المرحلة |

## معيار اكتمال الـMVP

النظام يُعتبر MVP جاهزًا فقط عند نجاح اختبار الدورة الكاملة (Task 11 في `docs/tasks.md`): شراء خامات → مخزون → إنشاء غرفة → صرف خامات → تكلفة → دفع عميل → خزنة → مصروف إداري → خزنة → اكتمال الغرفة → ربح → نصيب الشركاء → سحب شريك → خزنة + حساب الشريك — بأرقام صحيحة رياضيًا ومطابقة لحساب يدوي مسبق.

**الأولوية دائمًا: Correctness > Business Logic > Data Integrity > Testing > UI polish.**
